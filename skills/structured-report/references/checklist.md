# 交付前自检清单

分两级。硬门禁六条全过才能交；优化项尽量过，未过的在文末标为已知缺口。

配额数值与门禁条目的最终定义在 `SKILL.md`，本文只做核对。

## 硬门禁（不过不能交）

- [ ] **口径已声明** —— 文档头部写明时间边界、数据来源、统计范围，读者能复现
- [ ] **结论在第一句** —— 不是背景、不是「本期做了以下工作」
- [ ] **范围没外扩** —— 每一节都是用户点名要的，没有自行添加下期计划 / 上期回顾 / 风险清单 / 附录
- [ ] **形态与密度合格** —— 内容层是列表，每项是「粗体短语 + 句子」且携带一个新事实
- [ ] **归属与出处已标** —— 无编造数字；他人产出注明提交者，转述数据注明出处，未验证结论前缀「判断：」
- [ ] **配额没超** —— 结论 1 句、章节 3 条、列表项 3 条（最多 5）、嵌套 2 层

## 优化项

### 结构

- [ ] 结论 ≤40 字，含判断和动作
- [ ] 同层级条目 MECE，分类轴单一
- [ ] 同层级句式平行
- [ ] 全文只用一个主框架
- [ ] 每节标题是结论句，不是主题词
- [ ] 只读标题能读通全文逻辑
- [ ] 没有把短语当章节标题用
- [ ] 段落只出现在单句结论和「判断：」归因两处

### 内容

- [ ] 每个判断都有数据支撑
- [ ] 每个数据都有基准（环比 / 同比 / 目标 / 行业）
- [ ] 事实、观点、转述三者分开且已标注
- [ ] 同一事实全文只出现一次，结论里说过的正文没复述
- [ ] 同类明细不超过 3 条，其余已合并成总计句
- [ ] 缩写首次出现有全称
- [ ] 数据缺口用「【待补：xxx】」标出，没有为用户未要求的内容留占位行

### 表格

- [ ] 表里放的是可横向纵向对比的数，不可对比的已改成列表
- [ ] 整列无数据的列已删掉，不是填满「待补」
- [ ] 同一列量纲一致
- [ ] 表下注明了口径与归属

### 文字

- [ ] 无铺垫句、过渡句、自我评价
- [ ] 无删除词：大幅 / 明显 / 显著 / 有效 / 基本上 / 一定程度上
- [ ] 无「进行了……的工作」类名词化表述
- [ ] 无超过 35 字的句子
- [ ] 无「正在推进中」「后续跟进」等无主体表述
- [ ] 没统计字数、没标字数

### 行动项（仅当用户要求写计划或待办时适用）

- [ ] 每条符合 SMART，有 Owner、有 Deadline、有可验证的完成标准
- [ ] Deadline 是已确认的时间点；若为建议值，已注明

### 对人

- [ ] 风险和坏消息在前，不埋结尾
- [ ] 明确写出需要对方做的决策，或写「无需决策」
- [ ] 详略匹配受众身份
- [ ] 若含承诺回顾节，上次每一项都有回应

## 终检两问

- [ ] So What：每句话能答出「所以呢」
- [ ] Why：每个结论能答出「凭什么」
