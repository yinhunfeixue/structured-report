# 框架选用与模板

一份文档只用一个主框架。条目数的建议值见 `SKILL.md`「篇幅与条目数」，那是建议不是门禁 —— 内容需要几条就写几条。

## 选择表

| 场景 | 框架 | 一句话判据 |
|---|---|---|
| 汇报进展、说明现状 | 金字塔 | 对方只需知情 |
| 提出问题、申请资源 | SCQA | 需要对方掏资源或拍板 |
| 陈述成绩、述职 | STAR | 需要对方认可你的贡献 |
| 多方案选型 | 维度矩阵 | 需要对方在选项间做选择 |
| 事故与复盘 | 时间线 + 5 Why | 需要对方接受归因和改进 |

---

## 金字塔（论·证·类·比）

```
论：核心结论（一句话）
├─ 证 1：支撑要点  →  数据 / 事实
├─ 证 2：支撑要点  →  数据 / 事实
└─ 证 3：支撑要点  →  数据 / 事实
```

- 论：全文唯一结论，一句话
- 证：3 条起步，MECE，句式平行
- 类：每条证下的材料同类聚合
- 比：同层级按时间序 / 重要性序排列

## SCQA

| 段 | 内容 | 长度 |
|---|---|---|
| S 情境 | 双方共识的事实，不带情绪 | 1-2 句 |
| C 冲突 | 打破现状的变化或障碍 | 1-2 句 |
| Q 疑问 | 由冲突自然引出的问题 | 1 句 |
| A 回答 | 你的方案 + 需要的支持 | 主体 |

骨架：
> {现状量级，双方都认的数}（S）。{预期量级或新约束}，而{当前能力的上限}（C）。如何在 {期限} 内 {达成目标}（Q）？建议 {方案}，需要 {资源} 投入（A）。

四段必须是一条因果链：C 打破 S，Q 由 C 逼出，A 正面回答 Q。任一环节接不上，对方就会问「所以这跟前面有什么关系」。

## STAR

| 段 | 内容 |
|---|---|
| S 情境 | 当时的客观约束 |
| T 任务 | 你被要求达成什么，量化 |
| A 行动 | 你个人做的关键动作，2-3 个 |
| R 结果 | 量化结果 + 基准对比 + 沉淀 |

A 段只写自己做的，不写团队做的。R 段必须有数字。

## 维度矩阵

```
| 维度 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 成本 |  |  |  |
| 周期 |  |  |  |
| 风险 |  |  |  |
| 可维护性 |  |  |  |

推荐：方案 B。理由（≤3 条）。
放弃 A 的原因：一句话。
```

维度不超过 5 个，先列维度再填内容，避免为了凑结论挑维度。表格后必须给明确推荐，不给推荐等于把工作推回去。

## 时间线 + 5 Why

```
一、影响面
   受影响范围、时长、量级

二、时间线
   HH:MM  发生了什么（客观，不含判断）

三、根因
   现象 → 为什么 ×5 → 根因

四、改进项
   每条含 Owner + Deadline + 验证方式

五、已修复 / 待修复边界
```

时间线只写客观事件。归因放第三节，不要在时间线里夹判断。
