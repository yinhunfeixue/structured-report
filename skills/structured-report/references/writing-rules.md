# 精简改写规则

按顺序执行。验收标准是 `SKILL.md` 输出边界里的结构配额与信息密度，不是字数。

## 规则 0：先删超范围的整节

删字之前先删节。逐节问一句「用户要的是这个吗」，答否就整节删掉。

| 用户说 | 只写 | 不写 |
|---|---|---|
| 写 9 月工作汇报 | 9 月做了什么、结果如何 | 10 月计划、8 月回顾、风险清单 |
| 写这次故障复盘 | 时间线、根因、已做的修复 | 团队建设、季度 OKR |
| 写方案对比 | 维度矩阵、推荐项 | 实施排期、预算申请 |

删一节的收益顶得上删一百处用词。先做这步，后面的规则才有意义。

## 规则 1：删铺垫

删掉不承载信息的开场与过渡。

| 删 | 保留 |
|---|---|
| 首先，我想说明一下…… | 直接说 |
| 众所周知 / 不言而喻 | 删 |
| 在此背景下 / 基于以上 | 删 |
| 接下来我将介绍 | 删 |
| 总的来说 / 综上所述 | 仅在超长文档结尾保留 |

## 规则 2：删自评

汇报里不写对自己工作的评价，让数据说。

| 删 | 改 |
|---|---|
| 我们高度重视此事 | 删 |
| 团队付出了巨大努力 | 删 |
| 取得了显著成效 | 转化率 +23%（目标 +15%） |
| 我认为这个方案比较好 | 推荐方案 B，理由：…… |

## 规则 3：形容词换数字

删除词表：大幅、明显、显著、有效、较好、极大、充分、一定程度上、相对、基本上、大概。

| 原 | 改 |
|---|---|
| 性能大幅提升 | P95 从 1.8s 降到 0.9s |
| 用户反馈良好 | NPS 从 32 升到 48 |
| 基本完成 | 完成 8/10 项，剩余 2 项见附表 |

「基本完成」「初步上线」这类模糊进度必须换成分数或百分比。

## 规则 4：动词前置，去名词化

| 原 | 改 |
|---|---|
| 进行了性能的优化工作 | 优化了性能 |
| 对方案进行了讨论 | 讨论了方案 |
| 实现了对缓存的下沉 | 下沉了缓存 |
| 做出了相应的调整 | 调整了 X |

删除词：进行、实现、开展、完成了对……的、做出了相应的。

## 规则 5：拆长句

超过 35 字的句子必须拆。一句话一个信息。

| 原 | 改 |
|---|---|
| 由于近期流量增长较快导致数据库压力增大，我们经过分析后决定采取读写分离的方案并在上周完成了改造，目前来看效果不错。 | 流量环比 +40%，数据库 CPU 峰值达 92%。上周完成读写分离改造。当前 CPU 峰值 54%。 |

## 规则 6：被动改主动，补主体

| 原 | 改 |
|---|---|
| 该问题已被修复 | 张三于 10/12 修复 |
| 相关工作正在推进中 | 李四负责，预计 10/20 交付 |
| 需要进一步沟通 | 需产品侧在 10/15 前确认口径 |

「正在推进中」「后续跟进」不带 Owner 和时间，视为无效表述。

## 规则 7：术语一致

- 缩写首次出现给全称：`GMV（成交总额）`
- 同一概念全文一个叫法，不要「用户 / 客户 / 会员」混用
- 时间口径统一：要么全用「10/12」，要么全用「10 月 12 日」

## 规则 8：标题提炼

主题式标题 → 结论式标题。

| 原（主题词） | 改（结论句） |
|---|---|
| 数据概览 | `{主要指标}达标，{某项}是唯一缺口` |
| 问题分析 | `{问题}集中在{具体环节}，占 {X}%` |
| 后续计划 | `{周期}聚焦{单一重点}，需{资源}` |

三个改法的共性：主题词只说「这节讲什么」，结论句说「这节的答案是什么」。只读标题应该能读完整条逻辑链。

## 规则 9：明细留 Top 3

同类条目超过 3 条就抽一层。剩下的合并成一句总计，不逐条铺开。

| 原形态 | 改法 |
|---|---|
| N 行明细表，每行一句说明 | `处理 N 项。最重的 3 项：{三条}。其余 {N-3} 项 {共同特征}。` |
| N 项改动逐条展开 | 按影响面二分：`N 项改动，M 项改变对外行为：{M 条}。` |

判断留哪 3 条：对方看完会追问的留下，不会追问的合并。合并句必须给出共同特征，不能只写「其余略」。

## 规则 10：段落改列表项

正文里的信息段落改成「**粗体短语** —— 句子」的列表项。短语和句子在同一行，不要把短语升成标题。

| 原形态 | 改法 |
|---|---|
| 三段平铺的段落，各讲一件事 | 三个列表项，每项以粗体短语开头 |
| `### {短语}` + 下面跟一段说明 | 降级成 `- **{短语}** —— {把那段说明压成一句}。` |
| 只有 `- {短语}` 的裸列表 | 每条补一句：变化了多少、根因是什么 |

只有两种内容留作段落：单句结论，以及「判断：」开头的归因。

## 规则 11：表格只放可对比的数

表格的价值是让眼睛横向纵向扫。不能对比的内容用列表，不要塞进表格。

| 该用表 | 该用列表 |
|---|---|
| 同一组指标的本期 / 上期 / 目标 | 三件互不相干的进展 |
| 多方案在同几个维度上的取值 | 一件事的背景与归因 |
| 多条同构明细（时间、状态、Owner） | 长短不一的说明文字 |

三条硬规矩：

- **列全都有数才留** —— 整列无数据就删掉该列，不要整列填「待补」。无目标值就没有「目标」列。
- **同行必须可比** —— 一行指标的本期与上期要同量纲同口径。口径中途变过就拆成两行，或在该行注明变更点。
- **表下注口径** —— 数字的统计范围与归属写在表格下方，不要让读者猜（见 `principles.md` 第 19 条）。

单行表格没有对比价值，改成一句话。

## 整段诊断演示

下面这段是最常见的失败形态，不含任何可执行信息：

> 大家好，首先感谢各位参加本次汇报。过去一个季度，我们团队高度重视这项工作，进行了大量的优化和调整。经过不懈努力，目前数据有了比较明显的提升。同时我们也发现了一些问题，正在积极推进解决，后续会持续跟进优化。

逐句套规则，每一句都命中至少一条：

| 原句片段 | 命中规则 | 处置 |
|---|---|---|
| 大家好，首先感谢各位参加 | 规则 1 铺垫 | 删 |
| 高度重视、不懈努力 | 规则 2 自评 | 删 |
| 大量的优化和调整 | 规则 3 形容词无数字 | 换成改了几项、各改了什么 |
| 进行了……的工作 | 规则 4 名词化 | 动词前置 |
| 比较明显的提升 | 规则 3 删除词 + 缺基准 | 换成「从 X 到 Y，基准 Z」 |
| 发现了一些问题 | 规则 3 无量化 | 换成问题数与最重的那个 |
| 正在积极推进、后续持续跟进 | 规则 6 无主体无时间 | 补 Owner 与日期，或整句删 |

改写后的形态：

> 【结论】{核心指标}达目标 {X}%，但{缺口指标}低于目标 {Y}，需在{周期}优先修复。
>
> 【支撑】
> - **{短语}** —— {指标} {值}，高于基准 {值}。
> - **{短语}** —— {指标} {值}（目标 {值}），缺口集中在{具体环节}。
> - **{短语}** —— {根因数据}。
>
> 【待决】是否批准{资源}用于{动作}。

原文 5 句话 0 条可执行信息。改写后同等篇幅承载 7 条：3 个指标值、3 个基准、1 个根因定位。差别不在文采，在每句话有没有挂上一个可核对的数。
