# 结构化汇报写作

## 触发约束

本 skill 只在用户显式调用时生效。若当前请求不含上述显式指令，忽略本文件全部内容，按常规方式回应。

## 输出边界（优先于后面所有步骤）

不设字数上限。约束的是内容：写什么、写几条、每条携带多少信息。前两条管「写什么」，后三条管「怎么写」。

### 1. 范围锁定

用户的请求界定了一个范围：时段、主题、或对象。只写落在这个范围内的内容。

判据是逐节自问「这一节回答的是用户提的那个问题吗」。答否就删，不要留成「附带一提」。

两种情况必须分开，混淆会导致写多或写漏：

| 情况 | 形态 | 处置 |
|---|---|---|
| 超出范围 | 用户问 {范围 A}，内容讲 {范围 B} | 删。计划、回顾、预测都指向另一个时段 |
| 范围内但未点名 | 用户问 {范围 A} 的进展，内容是 {范围 A} 的坏消息 | 写。同范围的负面事实属应报内容 |

- **不等于只写好消息** —— 范围内的风险与失败必须报，按第 18 条原则前置。但不单开一节铺成清单，挂在对应进展项后面，用「判断：」标注。
- **模板是菜单不是清单** —— `assets/` 里的章节按需取用，用不到的整节删掉，不留空壳、不用「无」或「待补」占位。
- **宁缺勿多** —— 缺了用户会问，多了用户得自己删。

### 2. 归属与出处

三类内容必须标注，否则是虚报：

| 情况 | 写法 |
|---|---|
| 成果里含他人产出 | 注明产出者与分工边界 |
| 数据转自他人材料、日志、系统记录 | 注明出处，如「据 {来源}」 |
| 结论未经二次验证 | 前缀「判断：」或「推测：」 |

指标比正文更容易失信。一个「从 X 增长到 Y」的指标，若增量里含他人产出，必须在表下注明分工，否则整张指标表连带失信。

### 3. 结构配额

| 层级 | 配额 | 超了怎么办 |
|---|---|---|
| 结论 | 1 句，≤40 字 | 拆不掉说明没想清 |
| 支撑 / 章节 | 3 条，最多 5 | 上抽一层重新归类 |
| 每节的列表项 | 3 条，最多 5 | 留 Top 3，其余合并成一句总计 |
| 每个列表项 | 1~2 句 | 拆成两项，或把第二句降级删掉 |
| 单句长度 | ≤35 字 | 拆成两句，枚举句可放宽 |
| 嵌套深度 | 节 → 列表项，2 层 | 第三层的内容并进父项 |

单句长度与篇幅是两件事：句子有字数上限，全文没有。不要因为「不统计字数」就写长句。

### 4. 信息密度

每个列表项必须携带一个新事实，属于下面四类之一：

| 类型 | 形态 |
|---|---|
| 数据 | 某个量从 X 变成 Y，或达到 X（配基准） |
| 根因 | 现象由某个具体机制引起 |
| 状态变化 | 某项能力从不可用变可用，或边界发生移动 |
| 口径定义 | 某个指标的统计范围是什么 |

- **四类之外的删掉** —— 判据是去掉这项，读者会不会少知道一件事。
- **只有动作与感受的删掉** —— 「完成了重构，结构更清晰」「修复了若干问题」「推动了对齐」，三句都答不出「所以呢」。
- **同一事实只出现一次** —— 在结论里说过的，正文不再复述。

### 5. 内容形态

正文优先列表，不用段落堆叠。每项 = 粗体短语 + 破折号 + 句子，两者同一行：

```
- **{4~8 字短语}** —— {一句话，含数据或根因}。
```

| 错误形态 | 问题 |
|---|---|
| 只有短语的列表项 | 扫得快但读不懂，对方还得来问 |
| 只有句子的列表项 | 要读完才知道这条讲什么 |
| 短语当 `###` 标题，下面跟段落 | 短语占了标题层，目录读不出结论 |

- **标题层归结论句** —— 见 `references/principles.md` 第 14 条，短语下沉到列表项。
- **段落只用两处** —— 单句结论，或「判断：」开头的归因。
- **表格另有规则** —— 见 `references/writing-rules.md` 规则 11。

## 第一步：固化口径（素材未确认时不要开写）

汇报错在口径上，整篇作废；错在文字上，改几句就好。所以先做这步。

动手前把下面这张表填满，填不出的问用户：

| 项 | 要确认什么 | 常见坑 |
|---|---|---|
| 数据源 | 从哪个库 / 仓库 / 文档取，命令或路径写下来 | 只看单一来源，漏掉另一半素材 |
| 时间边界 | 起止日期，含不含边界当天 | 跨年歧义；素材实际不满整个周期却按整周期报 |
| 主体标识 | 人名 / 账号 / 团队的全部别名 | 同一主体有多个标识，按一个查会漏 |
| 纳入排除 | 哪些算、哪些不算 | 自动化产出、他人代操作、重复记录 |
| 基准来源 | 上期 / 目标 / 同比的数取自哪 | 有数据无基准，等于没有信息 |

- **口径写进文档头部** —— 让读者能复现，而不只是自己心里有数。
- **实际范围与用户说法冲突时按实际写** —— 并在头部说明差异，不要凑整成用户说的那个周期。
- **两期对比必须同跨度** —— 跨度不等时注明，不要让读者误以为总量可比。

## 第二步：锁定五要素

| 要素 | 说明 | 缺失时 |
|---|---|---|
| 受众 | 老板 / 平级 / 下级 / 客户。决定详略与用词 | 必问 |
| 口径 | 见第一步 | 必问 |
| 决策点 | 需要对方做什么决定、给什么资源 | 先按「无需决策」写，成稿后追问一句 |
| 目的 | 让对方知道、认同、还是拍板 | 由受众与决策点推定 |
| 篇幅 | 走结构配额，不按字数 | 用默认配额 |

只有受众和口径值得停下来问。其余取默认值继续写，成稿后一次性确认，不要为每一项各问一轮。

## 第三步：结论先行

开头就是结论，不是背景。固定形态：

```
【结论】一句话，含判断和动作。
【支撑】列表项，每条 = **粗体短语** —— 一句话展开。
【待决】需要对方拍板的事项，没有就写"无需决策"。
```

条目数与句长走结构配额，此处不复述数值。禁止开篇写「本周我们做了以下工作」「首先介绍一下背景」。

## 第四步：搭骨架

选一个框架，不混用。详见 `references/frameworks.md`。

- **汇报进展** —— 金字塔（论·证·类·比），对方只需知情。
- **提出问题求资源** —— SCQA（情境·冲突·疑问·回答），需要对方掏资源。
- **讲个人或团队成绩** —— STAR（情境·任务·行动·结果），需要对方认可贡献。
- **做方案对比** —— 维度矩阵，需要对方在选项间做选择。

同层级条目必须 MECE（不重不漏），且句式平行：要么全是动宾短语，要么全是名词短语。

## 第五步：填证据

- **判断后跟数据，数据后跟基准** —— 基准取环比、同比、目标或行业值，缺基准的数字没有信息。
- **事实、观点、转述三分** —— 观点前加「判断：」，转述数据注明出处。
- **形容词换数字** —— 删掉「大幅」「明显」「有效」「显著」。

## 第六步：精简

执行 `references/writing-rules.md` 的改写规则。验收标准是内容判据，不是字数：

- **每项都携带新事实** —— 过第 4 条信息密度的四类测试。
- **每层都在配额内** —— 过第 3 条结构配额。
- **同一事实不出现两次** —— 结论与正文、正文与表格之间都算。
- **没有超范围的节** —— 过第 1 条范围锁定。

删的优先顺序：

1. 超范围的整节
2. 同一事实的第二次表述
3. 铺垫句、过渡句、自我评价
4. 修饰副词
5. 明细条目 —— 留 Top 3，其余合并成一句总计

自检两问：

- **So What** —— 每句话问「所以呢」，答不出就删。
- **Why** —— 每个结论问「凭什么」，答不出就补证据或降级为假设。

## 第七步：交付前自检

过 `references/checklist.md` 的硬门禁，全部通过才能交。优化项尽量过，未过的在文末标为已知缺口。

## 改写既有草稿

用户给的是草稿时，跳过第一步到第四步，改走诊断流程：

1. **查结论** —— 第一句是不是结论。不是就从正文里找出来提到开头。
2. **查范围** —— 有没有超出用户请求范围的节。有就删，不要保留改进版。
3. **查形态** —— 段落堆叠改列表项，短语标题降级成列表项。
4. **查密度** —— 逐项做四类测试，删掉只有动作与感受的项。
5. **查归属** —— 他人产出、转述数据、未验证结论是否标注。

输出「改写后全文」+「关键改动 3 条」，不逐句点评。原文的事实一条都不能丢，只重组和删冗余。

## 本文件自身的适用边界

输出边界五条是给**汇报文档**定的，不全部自指。本文件是供 agent 查阅的参考文档，按查阅路径组织，不按论证结构组织。

- **自指的两条** —— 内容形态与信息密度。本文件已遵守：正文用列表项，每项携带判据或反例。
- **不自指的两条** —— 结构配额与标题即结论。本文件有 13 个顶层节、步骤标题是动宾短语，这是参考文档的正确形态；套用汇报配额会把流程挤成不可查的一团。
- **范围锁定只对汇报生效** —— 本文件要覆盖全流程，不存在「用户没点名要的节」这回事。
- **不写业务场景** —— 规则与示范一律用占位符和抽象类型，不写行业、产品、模块、真实指标名。可用通用数值示范语言规则（如「P95 从 1.8s 降到 0.9s」），但不引入业务背景。绑定业务的规则无法迁移，也会把使用者的内部信息留在 skill 里。
- **冲突以本文件为准** —— 配额数值只在本文件声明；门禁的具体条目只在 `checklist.md` 声明，本文件只引用不复述条数。`references/` 只做展开与举例。

## 输出约定

- **直接给成稿** —— 不解释写作过程。
- **不编造数字** —— 数据缺口用 `【待补：xxx】` 占位，但不为用户没要求的章节建占位行。
- **不统计字数** —— 篇幅由结构配额与信息密度决定，句长另有上限。
- **想加的内容成稿后再问** —— 用户没要求的不直接写进文档，成稿后单独问一句「要不要补 X」。
